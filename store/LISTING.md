# Play Console listing content for Codefall

Everything the Play Console asks for, ready to paste. Artwork sits alongside this
file and is regenerated by `tools/store_assets.py`.

## Submission order

Roughly the order the Play Console wants things, so nothing blocks on something
undone.

1. **Create the app.** All apps > Create app. Name `Codefall`, English (US),
   App (not Game), Free. The name is editable later; the package name is not.
2. **Upload the bundle first**, before filling in the listing — it surfaces any
   manifest or signing complaint while the rest is still cheap to change.
   Testing > Internal testing > Create release, upload `dist/Codefall-v1.4.aab`.
   Accept **Play App Signing** when prompted: the key in `keystore.properties`
   becomes the *upload* key, and Google holds the app signing key.
3. **Install from internal testing on a real device** and use it. This is the
   last point where a problem is cheap to fix.
4. **Store listing.** Short and full description below; the artwork in this
   folder.
5. **App content**, worked top to bottom: privacy policy URL, ads (none), app
   access (no login), content rating questionnaire, target audience, data safety
   (see below), government apps (no), financial features (none).
6. **Countries and pricing.** Free, and pick your countries.
7. **Production**, once the Console stops listing blockers.

### The closed-testing requirement

A **personal** developer account generally has to run a closed test with at
least 12 testers opted in continuously for 14 days before it can apply for
production access. An **organisation** account does not.

Google has moved these rules more than once, so trust the Console over this
file: the Dashboard lists exactly what it wants before it will let you publish.
If the requirement applies, start it early — it is the longest pole by far, and
everything else here can be finished while the clock runs.

Internal testing (up to 100 testers, no wait) is separate and available
immediately. Use it for step 3 regardless.

## Full description (max 4000 characters)

```
Codefall turns your phone into a wall of falling code.

Tune it to taste and watch it live: eight colour themes, six character sets, and
sliders for speed, glyph size, column density, trail length and glyph churn. The
preview at the top of the settings screen updates as you drag, so you can dial in
the look before you commit to it.

Run it three ways:

- Fullscreen screensaver, launched from the app. Tap anywhere to exit.
- System screensaver (daydream), so Android starts it while your phone is
  docked or charging.
- Live wallpaper behind your home screen, running at a lower frame rate to stay
  easy on the battery.

FEATURES

- Eight colour themes: Classic Green, Amber CRT, Ice Cyan, Red Pill, Neon
  Violet, Gold, Ghost White, and a Rainbow mode that sweeps hue across the
  columns and drifts over time.
- Six character sets: Katakana, Binary, Hexadecimal, ASCII, Symbols and Mixed.
- Mirrored glyphs for a more authentic look, switchable.
- Tilt steering: turn it on and the rain leans toward whichever edge of the
  phone you tip down.
- Secret messages: type any text and the code periodically resolves into it,
  holds for a moment, then dissolves back into noise.
- Optional clock in 12 or 24 hour format, resizable and positionable anywhere
  on screen.
- Six stacking CRT screen filters: scanlines, aperture grille, vignette,
  flicker and roll, static, and RGB fringing.
- Glow and glitch effects, each independently adjustable.
- Randomise button for looks you would not have dialled in by hand.

PRIVACY

Codefall requests no permissions at all. It has no internet access — the app
cannot send data anywhere because it never asks for the ability to. No ads, no
analytics, no crash reporting, no third-party SDKs, no trackers. Your settings
are saved on your device and are deleted when you uninstall.

If you switch on tilt steering, the gravity sensor is read only while the rain is
on screen, only to decide which way the code leans, and the readings are never
stored or sent anywhere.

Works on Android 5.0 and later.
```

## Artwork checklist

| Asset | Spec | File |
| --- | --- | --- |
| App icon | 512x512, 32-bit PNG | `icon-512.png` |
| Feature graphic | 1024x500, 24-bit PNG | `feature-graphic-1024x500.png` |
| Phone screenshots | 2-8 required, 1080x1920 | `screenshot-1..7-*.png` |

Seven screenshots: five of the rain itself and two of the settings screen.

The settings shots are captured by `SettingsShotTest` through Robolectric, so the
controls are drawn by the real Android view code with the real layout, labels and
slider values rather than being mocked up. The one part that cannot draw itself
there is the preview panel: a SurfaceView renders through a separate surface and
leaves a hole in the view hierarchy's own draw pass, so the rain is rendered
separately and composited into exactly the rect the SurfaceView occupies — which
is what a device shows in that panel.

Worth a glance against a real device capture before publishing, since system font
and widget theming can differ slightly by OEM.
